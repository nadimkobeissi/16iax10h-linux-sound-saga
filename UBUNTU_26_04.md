# Ubuntu 26.04 Speaker Fix Guide for the Lenovo Legion Pro 7 16IAX10H

This guide documents the steps that fixed very low or poor quality internal speaker audio on a Lenovo Legion Pro 7 16IAX10H running Ubuntu 26.04. It uses the AW88399 firmware and the Linux 7.0 patch from this repository, then builds Debian packages for the patched kernel with Ubuntu's tooling.

## Tested system

- Laptop: Lenovo Legion Pro 7 16IAX10H
- Distribution: Ubuntu 26.04 LTS, codename `resolute`
- Original kernel: `7.0.0-15-generic`
- Patched kernel generated by this guide: `7.0.0-legion-audio`
- Codec initially detected: Realtek ALC287
- Symptom: internal speakers worked, but volume and quality were very poor
- Probable cause: the AW88399 amplifiers were not initialized by the generic kernel

## Important warnings

1. This guide involves compiling and installing a custom kernel.
2. Keep the original Ubuntu kernel installed as a fallback.
3. If the patched kernel does not boot, enter GRUB, select `Advanced options for Ubuntu`, and boot the original kernel, such as `Ubuntu, with Linux 7.0.0-15-generic`.
4. If Secure Boot is enabled, the custom kernel will not boot unless it is signed manually. The easiest way to test this fix is to disable Secure Boot in BIOS/UEFI.
5. Do not delete the original kernel packages.
6. Run these steps while connected to AC power.
7. Do not close the terminal or suspend the laptop while the kernel is compiling.

## Phase 1: Initial diagnosis

Check the Ubuntu version and current kernel:

```bash
lsb_release -a
uname -r
```

In the tested case:

```text
Ubuntu 26.04 LTS resolute
7.0.0-15-generic
```

Check ALSA and PipeWire audio devices:

```bash
aplay -l
pactl list short sinks
```

Expected result before the fix, approximately:

```text
card 1: PCH [HDA Intel PCH], device 0: ALC287 Analog [ALC287 Analog]
alsa_output.pci-0000_80_1f.3.analog-stereo
```

Test the speakers:

```bash
speaker-test -t wav -c 2
```

If there is sound, but it is very low or poor quality, continue. You can also test with a sine wave:

```bash
speaker-test -t sine -f 440 -c 2
```

Check kernel messages related to audio:

```bash
sudo dmesg -T | grep -iE "aw88399|alc287|snd|codec|firmware" | tail -150
```

Before the fix, the tested system showed messages similar to:

```text
ALC287: picked fixup for PCI SSID 17aa:0000
speaker_outs=0
```

The `aw88399` driver did not appear.

Check whether the AW88399 firmware already exists:

```bash
ls -l /lib/firmware/aw88399_acf.bin
find /lib/firmware -iname "*aw88399*" -o -iname "*aw88*"
```

If the firmware does not exist, continue.

## Phase 2: Install basic tools and clone this repository

Install Git:

```bash
sudo apt update
sudo apt install -y git
```

Clone this repository:

```bash
cd ~
git clone https://github.com/nadimkobeissi/16iax10h-linux-sound-saga.git
```

If it already exists:

```bash
cd ~/16iax10h-linux-sound-saga
git pull
```

Check what the fix contains:

```bash
cd ~/16iax10h-linux-sound-saga
find fix -maxdepth 3 -type f | sort
```

In the tested case, the repository contained:

```text
fix/firmware/aw88399_acf.bin
fix/patches/16iax10h-audio-linux-6.19.11.patch
fix/patches/16iax10h-audio-linux-7.0.patch
```

## Phase 3: Install only the AW88399 firmware

Copy the firmware:

```bash
sudo mkdir -p /lib/firmware
sudo cp ~/16iax10h-linux-sound-saga/fix/firmware/aw88399_acf.bin /lib/firmware/aw88399_acf.bin
```

Verify it:

```bash
ls -l /lib/firmware/aw88399_acf.bin
```

It should show a regular root-owned file at `/lib/firmware/aw88399_acf.bin`.

Regenerate initramfs and reboot:

```bash
sudo update-initramfs -u
sudo systemctl reboot -i
```

After rebooting, test again:

```bash
speaker-test -t wav -c 2
sudo dmesg -T | grep -iE "aw88399|alc287|snd|codec|firmware" | tail -150
```

If the audio is still low and `aw88399` does not appear in `dmesg`, the firmware alone is not enough. Continue with the patched kernel.

## Phase 4: Optional test with `snd-hda-intel model=laptop-amic`

This test was performed, but did not solve the problem on the tested system. It is included for completeness.

Create a configuration file:

```bash
sudo nano /etc/modprobe.d/alsa-legion.conf
```

Add this line:

```text
options snd-hda-intel model=laptop-amic
```

Regenerate initramfs and reboot:

```bash
sudo update-initramfs -u
sudo systemctl reboot -i
```

Test again:

```bash
speaker-test -t wav -c 2
sudo dmesg -T | grep -iE "aw88399|alc287|snd|codec|firmware" | tail -150
```

If there is no improvement, remove the change:

```bash
sudo rm /etc/modprobe.d/alsa-legion.conf
sudo update-initramfs -u
```

## Phase 5: Prepare the patched kernel build

Confirm the current kernel and files in `/boot`:

```bash
uname -r
ls /boot
```

Install build dependencies:

```bash
sudo apt update
sudo apt install -y build-essential flex bison libssl-dev libelf-dev bc dwarves pahole \
  libncurses-dev fakeroot rsync wget xz-utils cpio python3 debhelper-compat libdw-dev gawk
```

The tested build required `debhelper-compat`, `libdw-dev`, and `gawk`, so they are included directly in the command above.

Create a working directory:

```bash
mkdir -p ~/kernel-audio-fix
cd ~/kernel-audio-fix
```

Download and extract Linux 7.0:

```bash
wget https://cdn.kernel.org/pub/linux/kernel/v7.x/linux-7.0.tar.xz
tar -xf linux-7.0.tar.xz
cd linux-7.0
```

## Phase 6: Apply the repository patch

Copy and apply the Linux 7.0 patch:

```bash
cd ~/kernel-audio-fix/linux-7.0
cp ~/16iax10h-linux-sound-saga/fix/patches/16iax10h-audio-linux-7.0.patch .
patch -p1 < 16iax10h-audio-linux-7.0.patch
```

Expected result:

```text
patching file drivers/acpi/scan.c
patching file drivers/platform/x86/serial-multi-instantiate.c
patching file sound/hda/codecs/realtek/alc269.c
patching file sound/hda/codecs/side-codecs/Kconfig
patching file sound/hda/codecs/side-codecs/Makefile
patching file sound/hda/codecs/side-codecs/aw88399_hda.c
patching file sound/hda/codecs/side-codecs/aw88399_hda.h
patching file sound/hda/codecs/side-codecs/aw88399_hda_i2c.c
patching file sound/hda/codecs/side-codecs/aw88399_hda_property.c
patching file sound/hda/codecs/side-codecs/aw88399_hda_property.h
patching file sound/soc/codecs/aw88399.c
patching file sound/soc/codecs/aw88399.h
```

If `FAILED` appears, stop and investigate before continuing.

## Phase 7: Configure the kernel

Copy the current Ubuntu kernel configuration:

```bash
cp /boot/config-7.0.0-15-generic .config
```

Enable the AW88399 modules:

```bash
scripts/config --module SND_HDA_SCODEC_AW88399
scripts/config --module SND_HDA_SCODEC_AW88399_I2C
scripts/config --module SND_SOC_AW88399
```

Run `olddefconfig`:

```bash
make olddefconfig
```

Give the kernel a custom name:

```bash
scripts/config --set-str LOCALVERSION "-legion-audio"
make olddefconfig
```

Check it:

```bash
grep CONFIG_LOCALVERSION .config
grep AW88399 .config
```

Expected result:

```text
CONFIG_LOCALVERSION="-legion-audio"
CONFIG_SND_HDA_SCODEC_AW88399=m
CONFIG_SND_HDA_SCODEC_AW88399_I2C=m
CONFIG_SND_SOC_AW88399=m
```

## Phase 8: Fix Ubuntu certificate configuration

When using the Ubuntu kernel configuration with vanilla Linux sources, the build may fail with:

```text
No rule to make target 'debian/canonical-certs.pem', needed by 'certs/x509_certificate_list'
```

Clear the Ubuntu-specific certificate paths and disable automatic module signing for this custom build:

```bash
cd ~/kernel-audio-fix/linux-7.0
scripts/config --set-str SYSTEM_TRUSTED_KEYS ""
scripts/config --set-str SYSTEM_REVOCATION_KEYS ""
scripts/config --disable MODULE_SIG
scripts/config --disable MODULE_SIG_ALL
make olddefconfig
```

Check it:

```bash
grep -E "SYSTEM_TRUSTED_KEYS|SYSTEM_REVOCATION_KEYS|MODULE_SIG" .config
```

The output should include at least:

```text
CONFIG_SYSTEM_TRUSTED_KEYS=""
CONFIG_SYSTEM_REVOCATION_KEYS=""
```

Even if `CONFIG_MODULE_SIG` remains set to `y`, it did not prevent compilation on the tested system.

## Phase 9: Disable unnecessary AMD graphics drivers

The first tested build attempt failed while compiling AMDGPU code. Since the tested Legion uses Intel graphics plus NVIDIA, AMDGPU and Radeon were disabled:

```bash
cd ~/kernel-audio-fix/linux-7.0
scripts/config --disable DRM_AMDGPU
scripts/config --disable DRM_RADEON
make olddefconfig
```

Check it:

```bash
grep -E "CONFIG_DRM_AMDGPU|CONFIG_DRM_RADEON" .config
```

Expected result:

```text
# CONFIG_DRM_AMDGPU is not set
# CONFIG_DRM_RADEON is not set
```

## Phase 10: Compile the kernel

Partially clean the build tree:

```bash
cd ~/kernel-audio-fix/linux-7.0
make clean
```

Compile Debian packages while saving the build log:

```bash
make -j8 bindeb-pkg 2>&1 | tee ~/kernel-audio-fix/build.log
```

On a powerful machine, this may take 30 to 90 minutes. It can use a lot of CPU and make the fans spin up.

If it fails, search the log for common errors:

```bash
grep -nEi "error:|fatal:|undefined reference|No rule|No such file|failed|conflicting|implicit declaration|killed|not found|canonical" ~/kernel-audio-fix/build.log | tail -120
```

Errors observed during the tested build included:

- Missing dependencies: `dpkg-checkbuilddeps: error: unmet build dependencies: debhelper-compat (= 12) libdw-dev:native`
- Missing `gawk`: `/bin/sh: 1: gawk: not found`
- Ubuntu certificate path error: `No rule to make target 'debian/canonical-certs.pem'`

The successful build ended with output similar to:

```text
dpkg-deb: building package 'linux-image-7.0.0-legion-audio'
dpkg-buildpackage: info: binary-only upload (no source included)
```

## Phase 11: Check generated packages

When the build finishes:

```bash
cd ~/kernel-audio-fix
ls -lh *.deb
```

In the tested case, the following packages were generated:

```text
linux-headers-7.0.0-legion-audio_7.0.0-5_amd64.deb
linux-image-7.0.0-legion-audio_7.0.0-5_amd64.deb
linux-image-7.0.0-legion-audio-dbg_7.0.0-5_amd64.deb
linux-libc-dev_7.0.0-5_amd64.deb
```

Install only the headers and image packages. Normally, do not install the debug package because it is very large and is only needed for debugging.

## Phase 12: Install the patched kernel

Install the image and headers:

```bash
cd ~/kernel-audio-fix
sudo dpkg -i linux-headers-7.0.0-legion-audio_7.0.0-5_amd64.deb linux-image-7.0.0-legion-audio_7.0.0-5_amd64.deb
```

During installation, you should see output similar to:

```text
Found linux image: /boot/vmlinuz-7.0.0-legion-audio
Found initrd image: /boot/initrd.img-7.0.0-legion-audio
```

Update GRUB if it was not done automatically:

```bash
sudo update-grub
```

Check that GRUB knows about the kernel:

```bash
grep -i "legion-audio" /boot/grub/grub.cfg | head -20
```

## Phase 13: Secure Boot

If, after rebooting, you see:

```text
error: bad shim lock signature
error: you need to load the kernel first
```

Secure Boot is blocking the unsigned custom kernel.

The simple test option is to enter BIOS/UEFI, disable Secure Boot, save changes, and reboot. The advanced option is to sign the kernel manually and enroll a MOK key, but that is not covered here.

If you need to boot in the meantime, enter GRUB, select `Advanced options for Ubuntu`, and choose the original kernel, such as `Ubuntu, with Linux 7.0.0-15-generic`.

## Phase 14: Boot with the patched kernel

After disabling Secure Boot, reboot and start Ubuntu.

Check the running kernel:

```bash
uname -r
```

Expected result:

```text
7.0.0-legion-audio
```

If it does not boot by default, choose it manually in GRUB under `Advanced options for Ubuntu`.

## Phase 15: Verify that AW88399 loads correctly

Run:

```bash
sudo dmesg -T | grep -iE "aw88399|alc287|snd|codec|firmware" | tail -150
```

A good observed result included messages similar to:

```text
aw88399-hda ... Looking up properties for SSID 17AA3907
aw88399-hda ... Picked up properties for SSID 17AA3907
aw88399-hda ... AW88399 HDA side codec registered successfully
aw88399-hda ... Bound to HDA codec, channel 0
aw88399-hda ... Bound to HDA codec, channel 1
snd_hda_codec_alc269 ... bound ... aw88399_hda_comp_ops
```

This indicates that the AW88399 driver is working.

## Phase 16: Test audio

Test the speakers:

```bash
speaker-test -t wav -c 2
```

You should hear clear `Front Left` and `Front Right` output. Also test normal music or video playback.

Check devices:

```bash
aplay -l
pactl list short sinks
```

In the tested case:

```text
card 1: PCH [HDA Intel PCH], device 0: ALC287 Analog [ALC287 Analog]
alsa_output.pci-0000_80_1f.3.analog-stereo    PipeWire    ...    RUNNING
```

## Phase 17: What to do if a kernel update changes the booted kernel

If the sound becomes poor again later, check:

```bash
uname -r
```

If it does not show `7.0.0-legion-audio`, Ubuntu probably booted a newer generic kernel.

Temporary solution:

1. Reboot.
2. Enter GRUB.
3. Select `Advanced options for Ubuntu`.
4. Choose `7.0.0-legion-audio`.

Possible permanent options are to keep the patched kernel as the default, or recompile the patch for the new kernel if appropriate. Keep the original `7.0.0-15-generic` kernel as a fallback.

## Phase 18: Useful recovery commands

List installed kernels:

```bash
dpkg -l | grep linux-image
```

See available kernels in `/boot`:

```bash
ls /boot | grep vmlinuz
```

Update GRUB:

```bash
sudo update-grub
```

Remove the patched kernel, if necessary:

```bash
dpkg -l | grep legion-audio
sudo apt remove linux-image-7.0.0-legion-audio linux-headers-7.0.0-legion-audio
sudo update-grub
```

Do not remove the patched kernel if it is working and you want to keep the fix.
